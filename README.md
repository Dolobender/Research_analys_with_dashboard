# Исследовательский анализ рынка общественного питания Москвы

## О проекте

Данный проект представляет собой **комплексное исследование рынка общественного питания в Москве** на основе открытых данных.  
Цель — выявить **наиболее перспективные локации, категории заведений и сегменты** для инвестиций.

В ходе работы были:

- собраны и объединены данные;
- выполнена **предобработка** (очистка дубликатов, обработка пропусков, приведение типов);
- проведён **исследовательский анализ** (распределение по категориям, районам, сетевость, посадочные места, рейтинги, корреляции, топ сетей, цены);
- сформулированы **практические рекомендации** для инвесторов.

---

## Цели и задачи

**Цель:**  
Провести комплексный анализ рынка общественного питания в Москве для выявления наиболее перспективных локаций, категорий заведений и сегментов для инвестиций.

**Основные задачи:**

- Собрать и объединить данные о заведениях (информация и цены)
- Провести предобработку (очистка от дубликатов, обработка пропусков, приведение типов)
- Провести исследовательский анализ (EDA) для оценки конкуренции, популярных сетей, анализа цен и рейтингов
- Сформулировать рекомендации для инвесторов

---

## Данные

Проект использует два набора данных:

| Файл | Описание | Ключевые поля |
|------|----------|---------------|
| `rest_info.csv` | Информация о заведениях | Название, категория, адрес, район, количество мест, режим работы, рейтинг, признак сети |
| `rest_price.csv` | Ценовая информация | Ценовая категория, средний чек, стоимость чашки кофе |

**Общий объём данных:** 8406 записей (после объединения и очистки).

---

## Используемые технологии

Проект реализован на **Python 3.9+** с использованием следующих библиотек:

- **Pandas** — загрузка, обработка и агрегация данных
- **NumPy** — численные вычисления
- **Matplotlib / Seaborn** — визуализация данных
- **Phik** — расчёт корреляций для смешанных типов данных

---

## Этапы анализа

### 1. Загрузка и знакомство с данными

- Импорт библиотек
- Загрузка данных из CSV-файлов
- Первичный осмотр структуры и типов данных
- Объединение датасетов по полю `id`

### 2. Предобработка данных

- Приведение типов данных (числовые поля)
- Обработка пропусков (пропуски сохранены для сохранения статистической достоверности)
- Очистка от дубликатов (нормализация названий и адресов)
- Создание признака `is_24_7` (круглосуточная работа)

### 3. Исследовательский анализ данных (EDA)

- **Категории заведений:** анализ распределения по категориям
- **Районы Москвы:** распределение заведений по административным округам, выделение ЦАО
- **Сетевые vs несетевые:** доля сетей в целом и по категориям
- **Посадочные места:** анализ распределения, выбросы, медианные значения
- **Рейтинги:** распределение по категориям, сравнение средних значений
- **Корреляции:** расчёт корреляций между рейтингом и другими признаками с использованием коэффициента phik
- **Топ-15 сетей:** ранжирование по количеству заведений, средний рейтинг, категории
- **Цены по районам:** анализ среднего чека в зависимости от удалённости от центра

### 4. Итоговые выводы и рекомендации

- Обобщение ключевых инсайтов
- Практические рекомендации для инвесторов

## Рекомендации для инвесторов

### 1. Выбор формата
- Для **премиального сегмента** (целевой чек >1000 руб.) – открывать **ресторан или бар в ЦАО**.
- Для **масштабирования и быстрой окупаемости** (чек 500–800 руб.) – **кофейня или фастфуд** в спальных районах с хорошей проходимостью (Северный, Восточный, Южный округа).

### 2. Выбор локации
- **Дорогой сегмент** – ЦАО (высокая концентрация платёжеспособного спроса, несмотря на высокую аренду).
- **Средний и бюджетный сегмент** – Северный (средний чек 928 руб., медиана 650), Восточный (821/575) или Южный (834/500) округа – ниже аренда, хороший трафик.

### 3. Ценовая политика
- В ЦАО цены можно устанавливать на **30–40% выше**, чем в спальных районах, но важно соответствовать ожиданиям по качеству.
- В других округах – конкурентные цены, ориентир на медиану 600–700 руб., но с уникальными позициями (региональные блюда, авторские десерты).

### 4. Сетевая стратегия
- Рынок **фрагментирован** (82% заведений – несетевые) – хорошие возможности для создания новой сети.
- Рекомендуется начать с **одной-двух точек в спальных районах**, отточить модель (формат, меню, цены) и затем масштабироваться в другие округа и в ЦАО.

### 5. Дополнительные исследования
- Провести **полевое исследование** (наблюдение за трафиком, опросы) для понимания реальных предпочтений потребителей в целевых районах.

## Как запустить проект

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/Dolobender/Research_analysis_python.git
   cd Research_analysis_python
   ```

2. Создайте окружение и установите зависимости:
   ```bash
   python -m venv .venv && .venv/Scripts/activate
   pip install -r requirements.txt
   ```

3. Подготовьте данные.
   Исходные датасеты (`rest_info.csv`, `rest_price.csv`) — учебные данные
   платформы и в репозиторий не выкладываются. Сгенерируйте синтетические
   той же схемы:
   ```bash
   python make_synthetic_data.py
   ```
   Настоящие CSV, если они есть, кладутся в `datasets_real/` — тогда в
   дашборде можно выключить тумблер «Синтетические данные» и считать по ним.

4. Запустите Jupyter и откройте `Проект ИАД рынка еды.ipynb`:
   ```bash
   jupyter notebook
   ```

## Подпроект `advanced`: проверка выводов, скоринг и дашборд

Основное исследование описывает рынок. Надстройка в папке
[`advanced/`](advanced/README.md) доводит его до решения:

| Что | Где |
|---|---|
| **Проверка гипотез** — критерии, размеры эффекта, доверительные интервалы вместо утверждений «на глаз» | [`advanced/01_Статистическая_проверка.ipynb`](advanced/01_Статистическая_проверка.ipynb) |
| **Скоринг локаций** — оценка 0–100 для каждой пары «округ × категория» с проверкой на чувствительность к весам | [`advanced/02_Скоринг_локаций.ipynb`](advanced/02_Скоринг_локаций.ipynb) |
| **Интерактивный дашборд** — фильтры, KPI, матрица оценок, разбор любой связки | `advanced/app/dashboard.py` |
| **Общий код** — загрузка, очистка, валидация, критерии, модель | `advanced/src/` |

Запуск дашборда:

```bash
streamlit run advanced/app/dashboard.py
```

Полная пересборка (данные → ноутбуки → исполнение → проверка на ошибки):

```bash
python advanced/run_all.py
```

Ключевая поправка, которую вносит подпроект: на выборке в 8 тысяч наблюдений
статистически значимо почти любое различие, поэтому решает **размер эффекта**.
Практически значима только разница в чеке между центром и периферией;
различия рейтингов между категориями объясняют считанные проценты разброса —
строить на них выбор формата нельзя.
