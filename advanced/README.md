# Подпроект `advanced`

Надстройка над основным исследованием (`../Проект ИАД рынка еды.ipynb`).
Основной ноутбук описывает рынок; этот подпроект **проверяет его выводы
статистикой, превращает их в ранжированное решение и подаёт всё через
интерактивный дашборд**. Оригинал не изменяется — подпроект читает те же
данные и живёт в отдельной папке.

## Структура

```
advanced/
├── src/                       общий код: одна логика для ноутбуков и дашборда
│   ├── data.py                загрузка, очистка, валидация
│   ├── stats.py               критерии, размеры эффекта, бутстрэп
│   └── scoring.py             модель привлекательности «округ × категория»
├── app/
│   └── dashboard.py           Streamlit-дашборд (5 вкладок)
├── 01_Статистическая_проверка.ipynb
├── 02_Скоринг_локаций.ipynb
├── tests/                     pytest: данные, критерии, скоринг, дашборд
├── build_notebooks.py         ноутбуки собираются отсюда, а не правятся руками
├── add_bridge.py              вставляет ссылки на подпроект в оригинал
├── run_all.py                 полная пересборка одной командой
└── requirements.txt
```

## Запуск

Из корня репозитория, в активированном виртуальном окружении:

```bash
pip install -r advanced/requirements.txt
python make_synthetic_data.py          # если датасетов ещё нет
streamlit run advanced/app/dashboard.py
```

Ноутбуки подпроекта открываются в том же Jupyter, что и оригинал:

```bash
jupyter notebook
```

Пересобрать и переисполнить всё (данные → ноутбуки → проверка):

```bash
python advanced/run_all.py
```

Тесты (данные, критерии, скоринг и сам дашборд через `streamlit.testing`):

```bash
python -m pytest advanced/tests -q
```

## Что внутри

### 1. Статистическая проверка (`01_...`)

В основном исследовании выводы вида «различия невелики, но статистически
значимы» сделаны без единого теста. Здесь четыре гипотезы проверены явно:

| Нулевая гипотеза | Критерий | Что добавлено сверх p-value |
|---|---|---|
| Чек в ЦАО не отличается от остальных округов | Манна—Уитни | rank-biserial r, бутстрэп-ДИ разности медиан |
| Рейтинг одинаков во всех категориях | Краскела—Уоллиса | eps², попарные сравнения с поправкой Холма |
| Сетевость не зависит от категории | хи-квадрат | V Крамера |
| Рейтинг не связан с чеком | Спирмен | rho, lowess-сглаживание |

Главный вывод подпроекта: на выборке в 8 тысяч наблюдений значимо почти
всё, поэтому решает **размер эффекта**. Практически значима только разница
в чеке между центром и периферией; различия рейтингов между категориями
объясняют считанные проценты разброса и для решения бесполезны.

### 2. Скоринг локаций (`02_...`)

Каждая пара «округ × категория» получает балл 0–100 по пяти факторам:
свободность ниши, потенциал выручки, слабость конкурентов,
фрагментированность, размер рынка округа. Веса задаются явно — рекомендацию
можно оспорить предметно, а не «на вкус».

Отдельный раздел — **проверка на чувствительность**: три профиля инвестора
(осторожный, премиальный, масштабирующий) и пересечение их топ-10.
Устойчивое пересечение и есть рекомендация; связки, всплывающие только при
одном наборе весов, — свойство весов, а не рынка.

Ограничения модели перечислены в конце ноутбука честным списком: нет данных
об аренде и трафике, округ как единица анализа слишком крупный, веса
экспертные, а не выведенные из отклика.

### 3. Дашборд (`app/dashboard.py`)

Пять вкладок:

- **Рынок** — KPI-плитки, распределения, тепловая карта насыщенности
  «округ × категория», чек по округам, занятость сегментов сетями;
- **Скоринг локаций** — веса на слайдерах, матрица оценок, разбор любой
  связки на вклады факторов и радар-профиль;
- **Проверка гипотез** — сводка критериев, разворачиваемые карточки с
  деталями, попарные сравнения;
- **Сети** — топ-20 сетей, масштаб против качества;
- **Данные** — отчёт о заполненности, срез под фильтрами, выгрузка в CSV.

Фильтры в сайдбаре применяются ко всем вкладкам сразу. Компактные (тип
заведения, рейтинг) стоят первыми, списки — ниже: пустой список значит «все»,
поэтому по умолчанию виджеты не забиты чипами. Округа в фильтрах подписаны
аббревиатурами (ЦАО, ЮЗАО), на графиках — полными короткими именами.

## О данных

Исходные датасеты Практикума (`/datasets/rest_info.csv`, `/datasets/rest_price.csv`)
не выложены в репозиторий. Чтобы проект был воспроизводим, в корне лежит
`make_synthetic_data.py` — генератор данных **той же схемы** с распределениями,
подогнанными под цифры из основного README (доли категорий, округов,
сетевость, медианы мест и рейтингов, наценка ЦАО).

**Все числа в результатах — синтетические.** Методика настоящая, цифры — нет.
В дашборде это видно сразу: тумблер «Синтетические данные» в панели настроек
и плашка над показателями.

Чтобы считать по настоящим данным, положите оригинальные `rest_info.csv` и
`rest_price.csv` в `datasets_real/` — тумблер станет активным, и выключение
его переведёт весь дашборд на реальные цифры. Для ноутбуков то же самое:
`D.load(synthetic=False)`. Код при этом не меняется.
